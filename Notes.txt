LLM means Large language model is a kind of AI build on deep neural networks trained on large amount of text 
from the internet -- books, articles, websites and conversations to learns patterns of human Language.
It predict what text should come next.

When you ask an LLM a question, it doesn't "think" like a human does. Instead, 
it plays a very fast game of predicting the next most logical word, over and over again, 
based on the patterns it learned during its reading.

Simple Example: 
Predicting the Next Word If you say, "The sky is clearly...",

How does the LLM understand the meaning of a word?

An LLM does not understand a word exactly like a human does. It learns relationships between words from many examples during training.

---------------------------------------------------------------
How does an LLM work?

1. User gives input: The user asks, “What is Python?”
2. Tokenization: The model splits the text into small pieces called tokens.
3. Convert into numbers: Each token is converted into numbers so the model can process it.
4. Understand the context: The model looks at the words and their relationships to understand what the user is asking.
5. Predict the next word: The model predicts which token is likely to come next.
6. Select a token: The model selects a token based on its prediction.
7. Repeat: It predicts the next token again and again until the complete answer is generated.

[The model looks at the tokens and their relationships using attention.]
It Capture the meaning of the words in Scentence  = Attention.

1. User gives text          Example: What is Python?
2. Tokenization             The text is split into tokens
3. Tokens become numbers    Each token gets a token ID and is converted into a vector
4. Transformer              The model looks at the tokens and their relationships using attention
5. Prediction               The model gives probabilities for possible next tokens
6. Next token is selected   A token such as 'Python' or 'programming' is selected
7. Repeat                   The new token is added and the model predicts again until the answer is complete

How does it know if it's right or wrong?  RLHF


An LLM does not automatically know whether its answer is correct or wrong. 
It predicts the next token based on patterns learned during training, 
so sometimes it can generate incorrect information called hallucination.
To improve this, we use RLHF, which stands for Reinforcement Learning from Human Feedback.
It is a technique used to improve an LLM's responses based on human feedback.

First, the model generates different answers to a question. 
Then, humans rank the answers from best to worst.
 A reward model learns these human preferences, and 
 reinforcement learning is used to optimize the LLM to produce better answers.

1. The Action: You ask the model a question. It gives three different answers.
Imagine an AI gives two answers to the same question.

2. Human Feedback: A human expert reads the three answers. The human ranks
them: Answer A is great (give a treat), Answer B is okay, Answer C is wrong or
unsafe (bad dog).
3. Reinforcement Learning: The computer looks at the human's ratings. It
adjusts its own internal math so that next time, it is more likely to generate
answers like A, and less likely to generate answers like C

However, RLHF does not guarantee that every answer will be correct.

AI generates incorrect even when it sounds confident. This is called hallucination.

State Management ≠ exactly Memory Management
state management = memory management (it need to know prev chat)

State management in an LLM application means keeping track of the current conversation or task information so the LLM can use it in the next steps.

Example: User first says, “I have a fever.” Then says, “Suggest a doctor.” The system keeps the previous information so it can understand what the user is referring to.
In simple terms, state management helps the system keep track of what's happening in the current conversation or task.


State Management
----------------------

State = information about what is happening right now / what has happened in the current process.

For example, in an appointment booking system:

User: I have fever
AI: You need a General Physician.

User: Book me tomorrow.

The system needs to know:

Problem = fever
Specialization = General Physician
Date = tomorrow

That's state.

--------------------------------------------------------------

Memory

Memory is more about information that can be retained and used later.

For example:

User's name = John
User prefers morning appointments
Previous appointment = Dr. Smith

So:

State = current conversation/task information
Memory = information retained for future use

They are related, but not exactly the same thing.

RAG stands for Retrieval-Augmented Generation.
When a user asks a question, the system retrieves relevant information from external sources 
and provides it to the LLM as context. The LLM then generates an answer based on that information.
RAG helps answer questions using private or updated data without necessarily retraining the model.

"RAG is called Retrieval-Augmented Generation because the system retrieves relevant information, 
adds it to the LLM's context, and uses the LLM to generate an answer."


1. Retrieval = Finding information
The system searches your company PDF and finds the leave policy.
2. Augmented = Adding information
The system adds the retrieved leave policy to the user's question and gives both to the LLM.
3. Generation = Creating an answer
The LLM uses the question and the retrieved information to generate the answer: "Your company provides 12 casual leave days per year."


Private data: Answer questions using company documents or internal data.
Updated information: Retrieve current information without retraining the LLM.
Reduce hallucinations: Give the LLM relevant facts to help it answer accurately. RAG cannot guarantee that every answer will be correct.
Cost-effective updates: Update your documents or database instead of retraining the entire model whenever information changes.

Why do we use RAG? — Interview Answer
1. To access private data: RAG helps an LLM answer questions using company documents, PDFs, or internal databases.
2. To get updated information: RAG retrieves the latest information from external sources without retraining the entire LLM.
3. To reduce hallucinations: RAG provides relevant information to the LLM, helping it generate more accurate answers. However, it cannot guarantee that every answer will be correct.
4. To reduce update costs: When information changes, we can update the documents or database instead of retraining the entire LLM.

RAG Flow — Simple Explanation
RAG (Retrieval-Augmented Generation) works in two main stages: preparing the data and answering the user's question.
1. Data preparation (Storing) (before the user asks a question)

1. Collect documents: Upload PDFs, text files, or company documents.
2. Chunking: Split large documents into smaller pieces.
3. Embeddings: Convert each text piece into numerical representations.
4. Store: Save the embeddings and text in a vector database.

RAG stands for Retrieval-Augmented Generation. It works in two main stages.

**1. Data Preparation:**

First, we collect documents such as PDFs or text files. 
Then, we split the documents into smaller pieces called chunks. 
Next, we convert each chunk into embeddings and store them in a vector database.

**2. Retrieval and Answer Generation:**

When a user asks a question, we convert the question into an embedding 
and search the vector database for relevant information. 
Then, we send the retrieved information along with the user's question to the LLM. 
Finally, the LLM uses that information to generate an answer.

Easy way to remember
Collect → Chunk → Embed → Store → Retrieve → Generate
Simple example
A user asks: "What is the company's leave policy?"
1. The system retrieves the relevant information from a company document.
2. It sends that information to the LLM along with the question.
3. The LLM generates an answer based on the retrieved information.

A Vector Database is a database that stores vector embeddings and helps us find information based on meaning or similarity.
In simple words, it helps AI find information that is semantically similar to a user's question, even when the exact words are different.



A vector database is a database used to store vector embeddings and retrieve information based on semantic similarity.
First, an embedding model converts text into numerical vectors. The vector database stores these vectors 
and compares them with the user's query vector to find relevant information.
Vector databases are commonly used in RAG applications, semantic search, and AI chatbots. Examples include FAISS, ChromaDB, Pinecone, and pgvector.


-----------------------------------------------------
Traditional vs vector database?

A traditional database stores structured data in tables and helps us find exact information using queries.
commonly used to retrieve records using exact values and conditions.

But a vector database stores embeddings and helps us find information based on meaning.
retrieves information based on similarity in meaning.

For example, a traditional database can find products below ₹500,
a traditional database can find products below a specific price
while a vector database can find products related to a user's question even when the exact keywords are different.
In RAG, we use a vector database to retrieve relevant document chunks and pass them to the LLM to generate an answer.




Why do we use a Vector Database in RAG?

1. Zero-shot Prompting

Zero-shot prompting means giving an instruction to an LLM without providing any examples.
The model generates an answer based on its existing training and the instruction.

2. Few-shot Prompting

Few-shot prompting means providing a few examples in the prompt to help the LLM understand 
the expected pattern and generate a similar response.

3. Chain-of-Thought (CoT) Prompting (Interview keyword: Step-by-step problem-solving).

Chain-of-Thought prompting encourages an LLM to approach a problem through intermediate reasoning steps instead of jumping directly to an answer.
Chain-of-Thought prompting encourages an LLM to break a complex problem into smaller steps before arriving at an answer. It can help with tasks that require multiple reasoning steps.

4. ReAct — Reasoning and Acting

ReAct is a prompting approach that combines reasoning with actions. The LLM can decide when to use a tool, observe the result, and continue toward the final answer.

User asks: What is the weather in Chennai today?

Step 1: Reason
The AI identifies that it needs current weather information.

Step 2: Act
It calls a weather tool to get the current conditions.

Step 3: Observe
It receives the weather information from the tool.

Step 4: Answer
It uses the result to answer the user's question.

ReAct stands for Reasoning and Acting. It allows an LLM to decide what action is needed, use tools to get information, observe the results, and continue until it can provide an answer.

Tool Calling vs Function Calling — Interview Answer

Function calling allows an LLM to request a specific function to perform a task.
Tool calling allows an LLM to use external tools, such as functions or APIs, to get information or perform actions.
Both terms are often used interchangeably.

Example: What is the weather today?

2. LLM selects a tool
It requests the weather tool.

3. Application executes the function
The function calls the weather API and gets the result.

4. Result returns to the LLM
The application sends the function result back as a tool result.

5. LLM generates the final answer
It uses the result to answer the user.

First, the LLM selects the appropriate tool based on the user's request. 
Then, the application executes the corresponding function and sends the result back to the LLM. 
Finally, the LLM uses that result to generate the response.
